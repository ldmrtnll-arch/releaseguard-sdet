# ReleaseGuard v1.0.0

**Status:** Release candidate — unreleased.

## Highlights

ReleaseGuard v1.0.0 prepares a self-contained SDET and Quality Engineering portfolio around a controlled subscription system. The release candidate combines parallel-safe automation, real service and database boundaries, deterministic failure engineering, measurable quality gates, and sanitized failure evidence.

## SDET capabilities

- deterministic builders and API-first fixtures;
- API, browser, integration, and persistence testing;
- concurrent-subscription and double-charge prevention checks;
- provider retry, timeout, decline, idempotency, and fault-injection coverage;
- Pact consumer contracts and provider verification;
- automated axe checks and selective visual regression;
- warmed k6 smoke plus a measured controlled-load profile;
- retry-aware Playwright observability with JSON and Markdown outputs;
- parallel GitHub Actions pull-request gates and extended workflows.

## System under test

The repository owns a React/Vite client, a Fastify API, PostgreSQL migrations and reference data, and an independent deterministic Fastify Payment Provider. The product supports authentication and the complete subscription lifecycle needed to exercise the quality architecture.

## Test layers

The standard regression contains 111 logical tests across unit, provider, API, integration, Pact, Chromium UI, and accessibility layers. Four Linux visual comparisons and secondary/full-browser executions are reported separately. Performance smoke exercises four measured scenarios with correctness checks.

## CI/CD quality platform

Pull requests run Quality, API and integration, Contract, Chromium UI, Firefox UI smoke, WebKit UI smoke, Advanced quality, and Performance smoke in independent jobs. Full Chromium/Firefox/WebKit regression is weekly or manual; controlled load is manual. Evidence is sanitized and retained proportionally.

## Known limitations

- This release candidate is a local, controlled portfolio SUT; it is not a production financial platform.
- The fake provider is not a real payment gateway and no PCI claim is made.
- There is no Pact Broker, production deployment, distributed load generator, or historical observability store.
- External authorization and PostgreSQL commit are not a distributed transaction or exactly-once guarantee.
- Automated axe checks do not replace manual accessibility testing.
- Performance measurements are environment-specific and are not a capacity claim.

## Validation summary

The release-candidate process includes clean dependency installation and audit, static quality, all test layers, full Linux cross-browser regression, accessibility, deterministic visual comparison, k6 smoke, observability inspection, clean Docker builds, empty-database migrations, health checks, and the core demo flow. Publication remains gated on a green GitHub-hosted run after review.

No Git tag or GitHub Release has been created by this preparation.
